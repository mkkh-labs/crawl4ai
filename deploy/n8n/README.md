# n8n → Crawl4AI integration contract

Normative contract for the production caller (SPEC.md **M5**, **M6**).

The upstream `/crawl` API is **not** forked for n8n. Everything described here
happens on the caller's side; Crawl4AI keeps its v0.9.3 request/response shape
and gains no persistence. [`contract.py`](contract.py) is the executable
reference for these rules and is covered by `tests/gateway/test_n8n_contract.py`.

## Transport

| Element | Value |
|---|---|
| Base URL | `http://crawl4ai:11235` (private `automation_internal` network) |
| Endpoint | `POST /crawl` |
| Auth | `Authorization: Bearer <CRAWL4AI_API_TOKEN>` |
| Credential storage | n8n credential store only |

There is no public hostname. The compose service publishes no host port, so this
endpoint is reachable only from containers attached to `automation_internal`.

n8n must also allow the hostname through its own SSRF guard. With
`N8N_SSRF_PROTECTION_ENABLED=true`, n8n blocks 172.16.0.0/12 (Docker bridge
addresses) by default, so set exactly `N8N_SSRF_ALLOWED_HOSTNAMES=crawl4ai`
(no wildcard). Always call the gateway by that name: an IP-addressed URL stays
blocked, which is intended.

> **Never** paste the token into a workflow node, an expression, an exported
> workflow JSON, or a log line. Exported workflows are shareable artifacts; a
> credential reference is safe to export, a credential value is not.

## Request

MVP sends **one URL per job**, which keeps provenance and retry semantics
one-to-one with a run.

```json
{
  "urls": ["https://example.com"],
  "browser_config": {},
  "crawler_config": { "stream": false, "cache_mode": "bypass" }
}
```

`hooks` is omitted and `crawler_configs` is unused in the MVP. Both
`browser_config` and `crawler_config` are loaded by the server as **untrusted**
config, so fields the untrusted loader rejects will return `400`, not be
silently ignored.

## Response classification

A `2xx` alone does **not** mean the crawl succeeded — the gateway returns `200`
with a per-URL result that can itself have failed. Classify status *then* body.

| Response | `status` | `failure_class` | Retry? |
|---|---|---|---|
| `2xx`, well-formed, all results succeeded | `succeeded` | — | no |
| `2xx`, result failed at a blocking target | `failed_terminal` | `blocked_target` | no |
| `2xx`, result failed, cause unclear | `failed_terminal` | `unknown` | no |
| `2xx`, body missing `success`/`results` | `failed_terminal` | `content_contract` | no |
| `400`, `422` | `failed_terminal` | `validation` | no |
| `401`, `403` | `failed_terminal` | `auth` | no |
| `413` | `failed_terminal` | `validation` | no |
| `429` | `failed_retryable` | `rate_limit` | yes |
| `500`, `502` | `failed_retryable` | `server` | yes |
| `503` | `failed_retryable` | `capacity` | yes |
| `504` | `failed_retryable` | `deadline` | yes |
| other `4xx` | `failed_terminal` | `validation` | no |
| other `5xx` | `failed_retryable` | `server` | yes |
| transport error / timeout | `failed_retryable` | `network` | yes |

`413` is classed `validation` rather than `capacity`: it is a property of the
body we sent, so resending it unchanged cannot succeed. [A]

A `2xx` whose result failed is terminal on purpose. Re-requesting a page that
served a bot challenge is the retry storm `CLAUDE.md` forbids.

## Retry policy

- **Bounded**: `MAX_ATTEMPTS = 3` total attempts. Never unbounded.
- Retry **only** when the classification is retryable. Never blind-retry a `4xx`.
- Backoff is exponential (`2**attempt`), capped at 60s.
- Honor `Retry-After` when it is a delta-seconds value; fall back to backoff for
  the HTTP-date form.
- On budget exhaustion the run becomes terminal and must emit failure evidence
  (below), not disappear.

## Provenance envelope (`CrawlRun`)

Persisted by n8n/storage for **every** run, success or failure.

| Field | Source |
|---|---|
| `run_id` | generated by n8n *before* the request |
| `source_url` | input, with credential-bearing query values redacted |
| `started_at` / `finished_at` | n8n |
| `crawler_version` | `/health` or deployment metadata |
| `config_fingerprint` | `sha256` of canonical JSON of the request configs |
| `raw_response` | the complete response body, verbatim |
| `raw_checksum` | `sha256` of the canonical raw response |
| `status` | `succeeded` \| `failed_retryable` \| `failed_terminal` |
| `failure_class` | taxonomy entry, or `null` on success |
| `artifact_ref` | durable storage reference, when one was written |
| `attempts` / `failures` | attempt count and per-attempt `FailureRecord`s |

Canonical JSON is sorted-key and whitespace-free, so two semantically identical
configs fingerprint identically and runs stay comparable.

A rerun of the same source is a **new run**, never an overwrite. Evidence is
append-only; the fingerprint is what lets you compare two runs of the same
source.

### Secrets

`Authorization` and other credential headers, and credential-bearing query
values, must never reach a provenance record, an artifact, or a log. Failure
messages are stored as a `message_digest`, because upstream error strings can
echo the request URL — and therefore its query string — back to the caller.

## Failure taxonomy

`validation`, `auth`, `rate_limit`, `capacity`, `deadline`, `network`, `server`,
`content_contract`, `blocked_target`, `unknown`.

Every failure maps to exactly one. `unknown` is a real classification, not a
default to hide behind: it means the response was well-formed but the cause was
not determinable, and it still produces terminal evidence.

## Downstream events

| Event | Consumer | Minimum payload |
|---|---|---|
| `crawl.requested` | Crawl4AI | run_id, URL, config fingerprint |
| `crawl.succeeded` | artifact / registry / RAG | run_id, source, version, raw response + checksum |
| `crawl.retrying` | observability | run_id, failure_class, attempt, next delay |
| `crawl.failed` | registry + Linear | run_id, class, attempts, evidence ref |

## Status of downstream integrations

The Notion registry and Linear failure routing are **P1 and not configured in
this repository**. `contract.py` produces the data those steps require; no
Notion, Drive, or Linear identifier is fabricated here.
